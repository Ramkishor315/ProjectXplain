# Mid-Semester Evaluation Report Outline

This document outlines the structural framework and section-by-section contents of the comprehensive Mid-Semester Evaluation Report for **ProjectXplain**.

---

## Document Structure & Page Mapping (Target: 10–15 Pages)

| Section # | Section Title | Key Content & Technical Focus |
| :---: | :--- | :--- |
| **1** | **Cover Page** | Project Title, Academic Institution, Department, Team Members, Supervisor, Academic Year |
| **2** | **Abstract / Executive Summary** | High-level synthesis of ProjectXplain, core motivation, architecture, and current status |
| **3** | **Problem Statement and Motivation** | The viva voce preparation gap in undergraduate CSE education, limitations of industry tools |
| **4** | **Objectives** | Pedagogical and functional engineering objectives across the 10-feature progression |
| **5** | **Stakeholders** | Stakeholder matrix and student/evaluator user personas |
| **6** | **Scope** | Explicit boundaries: in-scope implemented features vs. out-of-scope enterprise extensions |
| **7** | **Functional Requirements** | Formal FR-01 through FR-11 requirements specifications with inputs, outputs, and validation |
| **8** | **Non-Functional Requirements** | Modest, student-grade quality attributes: latency, credential isolation, usability, referential integrity |
| **9** | **Product Backlog** | Prioritized items (P0 to P3) distinguishing Completed, In Progress, and Planned features |
| **10** | **User Stories & Use Cases** | Agile user stories with acceptance criteria; formal use cases (UC-01 through UC-07) |
| **11** | **System Design & Methodology** | 3-tier architectural methodology, modular design principles, and component responsibilities |
| **12** | **System Architecture** | Concrete client-server topology (Vite:5173, Express:4000, MySQL:3306, OpenRouter) |
| **13** | **Database Design** | Complete schema breakdown across all 13 MySQL tables, keys, types, and cascade rules |
| **14** | **API Design** | Strict distinction: (A) Real Platform REST APIs vs. (B) Educational Project-Designed APIs |
| **15** | **Request & Data Flow** | Feature 8 design: sequential step tracing, data movements, and viva preparation utility |
| **16** | **UI Design & User Experience** | Modern Tailwind CSS workspace layout, sidebar navigation, responsive cards, and badges |
| **17** | **Implementation Progress** | Verification of completed Features 1–10, codebase directory audit, and technical stack |
| **18** | **Computer Science Concepts Hub** | Feature 9: 5 curriculum subjects, 17 seeded concepts, 4-facet educational structure |
| **19** | **Context-Aware AI Mentor** | Feature 10: Server-side OpenRouter integration, context aggregation, viva prompt design |
| **20** | **Testing & Quality Assurance** | Test strategy, 55 test cases across functional/API/DB suites, honest execution metrics |
| **21** | **Project Management & Tracking** | Sprint methodology, milestone progress log, and meeting framework |
| **22** | **Individual Contributions** | Team roles (Saksham, Ravi, Ram Kishor, Priyanshu), verified Git commits vs. team tasks |
| **23** | **Technical Challenges & Solutions** | Port collisions (EADDRINUSE), blank-screen imports, AI context window assembly |
| **24** | **Current Limitations** | Single-user local scope, lack of authentication, absence of PDF export engine |
| **25** | **Remaining Work for End-Sem** | Export engine, automated test suite, interactive visual canvas, multi-user sharing |
| **26** | **Academic AI Usage Disclosure** | Full disclosure of Antigravity AI, OpenRouter API, human oversight, and integrity |
| **27** | **References** | Academic software engineering textbooks, official documentation, standards |
